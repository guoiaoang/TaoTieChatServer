# 设计说明

## 消息同步与监听

1. 每个用户一个单调递增可不连续的事件 ID，该事件 ID 可记录所有与该用户相关的事件列表。

2. 当客户端登陆时检查本地与服务器的事件 ID 是否一致，不一致时进行循环批量拉取，并在本地进行事件的分发处理。

3. 事件同步和监听为同一个接口，服务器收到新事件时从该接口发送消息内容给客户端。

4. 客户端主动发起的事件不走事件同步接口。

5. 发送聊天消息与接收聊天消息不是同一个接口。

    客户端发送聊天消息时由服务端进行事件 ID 的增加并同步到当前与其他客户端及其他用户，
    其他客户端或用户通过事件更新接口获取新消息的推送。

6. 消息 ID 与事件 ID 需要共存。

    由于事件 ID 与用户绑定且共同独立，不同用户同一条消息的事件 ID 不同，不利于同步与引用。

7. 事件 ID 可用户所有事件公用，也可不同类型分别计数。

8. 文件传输、群组信息更新等数据量较大的功能可另外设计。

9. 新设备登陆时获取的非同步内容如好友列表、群组列表等使用专门的接口。
